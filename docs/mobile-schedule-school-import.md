# 移动端从教务导入课表设计

## 目标

用户在应用内打开齐鲁工业大学教务系统，必要时手动登录，进入“个人课表查询”后选择学年、学期并点击学校原有的“输出EXCEL”按钮。应用接收该 Excel，复用现有课表解析与导入预览，最终由用户选择创建新课表或覆盖已有课表。

## 交互

1. 课表空状态和右上角菜单提供“从教务导入”。
2. 打开受限的教务 WebView；登录成功后自动进入个人课表查询页。
3. 页面提示用户选择学年、学期、点击“输出EXCEL”。
4. 下载完成后自动关闭教务页并展示现有导入预览；开学日期、总周数和创建/覆盖仍由用户确认。
5. 保留“从文件导入”，用于导入本地 XLS/XLSX 或同学分享的备份。

## 技术方案

- 新增专用 `ScheduleImportActivity`，沿用成绩查询的 HTTPS 域名白名单、证书错误拒绝策略和共享 WebView Cookie。
- 不复制教务页面的导出参数。注入最小拦截器，仅接管学校导出表单的提交，在同源环境中获取 Excel 响应并分块交给原生层。
- 原生层限制文件大小、校验传输长度和 SHA-256；`SchedulePlugin` 再复用现有 XLS/XLSX 读取逻辑生成行数据。
- Web 层继续调用既有 `parseScheduleRows`，因此“其它课程”、单双周、教师、地点以及导入预览规则保持一致。

## 安全与失败处理

- 只允许 `https://jw.qlu.edu.cn` 与 `https://sso.qlu.edu.cn`，阻止外域主页面跳转和任何证书绕过。
- 禁止 WebView 文件访问、内容访问、混合内容和第三方 Cookie。
- Excel 上限 20 MiB；传输摘要不一致、格式错误或教务页面结构变化时拒绝导入并给出可重试提示。
- 用户关闭或按返回键时取消本次导入，不改动已有课表。

## 验证

- 单元测试覆盖允许的课表页/导出地址和外域拦截。
- 运行现有课表解析测试、移动端类型检查与 Android 构建。
- 真机验证登录复用、学期切换、点击“输出EXCEL”后进入预览，以及取消/返回路径。
